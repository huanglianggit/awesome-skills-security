# Contributing

Thanks for helping improve Awesome Agent Skills Security.

## What Belongs Here

Submissions should materially help people assess, distribute, isolate, monitor, or
govern AI Agent Skills. Relevant categories include:

- purpose-built skill scanners and auditing skills;
- runtime isolation, least-privilege, and policy enforcement;
- provenance, signing, SBOM, and dependency controls;
- public security indexes and registries;
- reproducible benchmarks and defensive datasets; and
- specifications, peer-reviewed research, incident analysis, and substantive
  community discussions.

Generic AI or application-security projects should have a clear, documented use in
the Agent Skills threat model.

## Inclusion Requirements

A project listed as open source must have publicly inspectable source and an
explicit license. Every submission should also provide:

- a stable canonical URL;
- the security problem it addresses and where enforcement occurs;
- supported skill formats or agent ecosystems;
- whether it executes target code or uploads target content;
- a documented threat model or clear limitations; and
- tests, evaluation data, or reproducible examples where available.

Early-stage projects are welcome when their status is clear and they provide a
distinct security mechanism. Unlicensed, proprietary, hosted-only, and
source-available projects must be labeled accurately.

## Pull Request Checklist

- Add the entry to the most specific existing section.
- Use the canonical project name and primary source.
- Write a concise, factual description without “safe,” “first,” or “only” claims.
- Include the SPDX license identifier for open-source entries.
- Verify all changed links and check for redirects or repository renames.
- Avoid star counts and other fast-changing popularity metrics.
- Do not include direct installation commands, live malware, credential stealers,
  or links that bypass a project's safety warning.
- Update `Last reviewed` only after broader list verification, not for one entry.

## Corrections and Removals

Open a correction issue when an entry is abandoned, compromised, relicensed,
misleading, or no longer available. Include primary-source evidence where possible.
Security-sensitive reports should follow [SECURITY.md](SECURITY.md).
